# 微内核性能策略

Zero OS 采用微内核架构，但需要接近宏内核的性能。核心策略如下：

## 1. 零拷贝消息传递
- IPC 管道使用共享内存环形队列，消息头通过寄存器传递，数据采用页映射或 `grant table`。
- 批量唤醒：一次系统调用可处理多条消息，减少上下文切换。

## 2. 用户态驱动
- 驱动服务器（如存储、网络）运行在用户态，通过能力控制访问硬件。
- 微内核提供快速路径系统调用，利用 EL0/EL1 切换时的 `fastpath` 指令序列。

## 3. 时间片调度优化
- 采用基于 tickless 的调度器，空闲时进入 WFI，避免无谓轮询。
- 对 I/O 密集型服务器设置更短的优先级队列，减少请求排队时间。

## 4. 系统调用门控
- 对常用系统调用（发送/接收、共享内存映射）提供内联汇编快速通道。
- 使用能力令牌避免昂贵的权限检查，即验证一次、缓存多次。

## 5. 并行与 NUMA 规划
- 引入 `per-core scheduling domains`，每个 CPU 核心维护独立运行队列，减少锁竞争。
- 共享数据结构（如 IPC 映射）使用 RCU/无锁散列表。

## 6. 性能监测
- 微内核内置 tracepoint，用户态通过 `perftrace` server 拉取事件，方便定位瓶颈。
- 关键路径全部记录周期计数器（CNTVCT_EL0），与恢复模式结合用于诊断。

## 后续任务
- 实装共享内存 grant table 与页帧管理器。
- 完成 per-core runqueue，实现多核调度。
- 为前端应用提供 `libzero`，封装优化过的 IPC API。
