# Zero File System (ZFS) 规范草案

## 设计目标
- 为 Zero OS 微内核提供高性能、可扩展的磁盘格式。
- 兼容 `.app` 应用包：将整套应用目录视为原子单元存储，支持签名与回滚。
- 支持写时拷贝快照与恢复模式快速回滚。
- 对安全敏感数据提供区块级校验与可选的透明加密。

## 物理布局
1. **Primary Header**：位于 LBA0，记录超级块序列、镜像信息。
2. **Super Block 序列**：保存 `SuperBlock` 结构副本，采用循环校验字段。
3. **Cluster Groups**：由若干连续块组成，每个组含有：
   - 位图（数据/元数据）
   - 日志区段（intent journal）
   - Inode 表
   - 数据块区域
4. **Journal Ring**：全局写前日志，支持崩溃后回放。

## 关键结构
- `SuperBlock`：魔数 `0x5A465330302020`（ASCII `ZFS00   `），记录块大小、版本、根 Inode。
- `Inode`：固定大小 256 字节，包含 12 个内联数据指针 + B+ 树扩展根。
- `BundleHeader`：`InodeKind::AppBundle` 专用，记录 `main`/`config` 校验摘要及包版本信息。

## 元数据一致性
- 所有修改先写入 Journal，再异步合并到主结构。
- 快照在 Journal 中记录检查点号，通过 Copy-on-Write 块实现。

## 安全特性
- 超级块包含 `fs_uuid` 以及 HMAC 校验，恢复模式可验证完整性。
- `.app` 包目录至少包含 `main` 与 `config`，存储层可对二者做不可变校验；若存在 `CodeSignature`，可追加验证逻辑。

## 与微内核的交互
- ZFS 文件服务器通过 IPC 接受内核/用户请求，完成 Inode 查找、读写、目录维护。
- 服务器暴露`mount`, `lookup`, `read`, `write`, `snapshot`, `install_bundle` 等消息类型，采用 `zero-abi` 中定义的消息格式。

## 后续工作
- 补全 Journal 重放算法与块分配器实现。
- 制作 `mkzfs` 用户态工具，用于格式化磁盘、创建根文件系统。
- 设计 `.zpkg` 包管理格式与 `.app` 目录布局落地到 ZFS。

## 参考实现概览

仓库中的 `zero-zfs-core` 提供了最小可用的参考实现，用于支撑用户态 `zero-fs-zfs` 服务器：

- **块分配器**：`BlockAllocator` 以内存位图管理可用块，支持快照/恢复。
- **日志系统**：`Journal` 记录分配、写入与快照事件，为后续重放留钩子。
- **目录索引**：`DirectoryIndex` 使用 BTree 来维护路径到 Inode 的映射，并缓存块列表与文件签名。
- **挂载与 IO**：`Volume` 抽象块设备，负责加载超级块、导入引导文件、读写文件时触发签名校验、写入日志、更新索引。
- **快照**：`SnapshotManager` 能够捕获分配器与目录快照、列出/恢复，并通过 IPC 接口暴露给 `Snapshot` 请求。

用户态的 `zero-fs-zfs` 服务器基于上述接口实现了挂载、文件查找/读写、`.app` 包安装校验以及快照管理等操作，并通过简易协议在 `Message.payload` 中返回结果。

## 第十二刀选型结论（2026-08）

**命题**：fsd 目录树/多文件落地路径——扩展 zfs-core 元数据 vs fsd 层树状索引。

**决策**：本刀采用 **fsd 层「扁平全路径表 + 显式目录标记槽」** 方案，zfs-core
保持卷/分配器基建不动。理由：

1. **端到端可用优先**：fsd 现有块后端（blkdrv 直通）+ 超级块单扇区元数据已
   实机验证（fstest PASS）。在其上以最小增量（槽位名升级为全路径、目录用
   `path/` 尾斜杠标记槽表达、LIST 支持路径前缀过滤）即可交付 POSIX 风格的
   mkdir/list/unlink/rmdir 语义，风险集中在纯逻辑层，主机测试可钉死。
2. **超级块布局 v1 不变**：旧卷免迁移；`matches` 判据按「尾斜杠=目录标记」
   天然区分两类记录，向后兼容（旧卷文件全部位于根目录，行为不变）。
3. **zfs-core 落地延后的代价可控**：快照/日志等高级语义依赖元数据树化，
   待第十三~十四刀稳定后单独立项；届时 fsd 的 vtable 协议（0x20..0x27）
   已冻结，可整体替换后端而不动客户端。
4. **已知限制（披露）**：
   - 全路径 ≤ 23 字节（NAME_MAX-1）；更深嵌套需路径压缩或哈希目录项；
   - 槽位上限 MAX_FILES=8（文件+目录合计），扩容需超级块多扇区版本化；
   - 不支持 `.`/`..` 段与符号链接；rmdir 仅删空目录（POSIX 对齐）。

**验收锚点**：shell `fsdemo` 九步断言（mkdir→写读回→ls 断言→嵌套创建→
非空 rmdir 拒绝→unlink→级联 rmdir→消失复查）；主机侧 path_tests 五例
判定矩阵（规整/切分/标记往返/误配防御）。
